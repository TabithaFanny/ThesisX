# PRD — Knowledge Base

## 1. Module Goal

Knowledge Base is the core product layer that turns ThesisX from a Runtime shell into a real academic writing workstation.

It stores and connects:

1. LiteratureItem
2. NoteItem
3. TheoryItem
4. EvidenceItem
5. Claims
6. Project bindings
7. Tags
8. Relations

## 2. User Value

Users should be able to:

- Import research assets.
- Search them.
- Organize them by project.
- Extract theories and evidence.
- Use them as RAG context.
- See how AI writing is grounded.

## 3. Core User Flow

```text
Create Project
→ Add Research Question
→ Import Literature / Notes / Theories / Evidence
→ Search / Filter
→ Bind to Project
→ Build Context Bundle
→ Use in AI Draft
```

## 4. Object Types

### 4.1 LiteratureItem

1. title
2. authors
3. year
4. venue
5. doi
6. citation_key

## 5. Required Functions

### 5.1 Create Object

User can create:
- Literature
- Note
- Theory
- Evidence

### 5.2 Import Object

Supported initial import:
- Markdown
- BibTeX
- RIS
- Plain text
- Manual input

### 5.3 Search

Search by:
- keyword
- type
- tag
- project
- source
- citation key

### 5.4 Bind to Project

One object can belong to multiple projects.

### 5.5 Relations

Supported relation:
- literature supports evidence
- evidence supports claim
- theory frames claim
- note summarizes literature
- theory derived from literature
- object generated by run

## 7. Technical Requirements

### 7.1 Storage

Use SQLite:

```text
~/.wenbiao/thesisx.db
```

### 7.2 Services

Recommended files:

```text
app/core/knowledge/models.py
app/core/knowledge/database.py
app/core/knowledge/store.py
app/core/knowledge/search.py
app/core/knowledge/importers.py
```

### 7.3 APIs

```python
KnowledgeStore.create_object(data)
KnowledgeStore.update_object(id, patch)
KnowledgeStore.delete_object(id)
KnowledgeStore.get_object(id)
KnowledgeStore.search(query, filters)
KnowledgeStore.bind_to_project(project_id, object_id, role)
KnowledgeStore.create_relation(source_id, target_id, relation_type)
KnowledgeStore.get_relations(object_id)
```

## 8. RAG Integration

Knowledge Base must expose:

## 10. Acceptance Criteria

Knowledge Base is minimally usable when:

1. SQLite DB initializes automatically.
2. User can create project.
3. User can add all four object types.
4. User can search objects.
5. User can bind objects to project.
6. User can create relations.
7. User can see object detail.
8. RAG can read from KnowledgeStore.
9. Tests pass.
10. No network required.

## 11. Do Not Do Yet

Do not in first implementation:
- Full Zotero sync.
- Full Obsidian write-back.
- Cloud sync.
- Multi-user collaboration.
- Vector database server.
- Deleting imported source files.
